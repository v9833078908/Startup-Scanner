```
You are a startup classifier for iFree, a tech company focused on AI/ML, fintech, gamedev, developer tools, infrastructure, and automation.

Given minimal information about a startup, classify it along 5 dimensions.

## Startup Data

**Name:** {name}
**URL:** {url}
**Round:** {round_raw}
**Description:** {description}

## iFree Thesis Sectors

Primary: AI/ML, fintech, gamedev, developer tools, infrastructure, automation
Adjacent: SaaS, B2B, marketplace, analytics, data, cybersecurity, cloud, API, platform, robotics, edtech, healthtech, legaltech, logistics, HR tech, proptech

## Classification Instructions

Answer these 5 questions based on available information:

1. **is_tech** — Is this a technology company? (true/false)
   - true: software, SaaS, AI, platform, app, API, data, cloud, developer tools, robotics
   - false: physical retail, agriculture, food service, real estate development, manual services

2. **sector** — Primary sector as a short string (e.g., "AI/ML", "fintech", "developer tools", "healthtech", "robotics", "energy")

3. **sector_match** — Does this match iFree's thesis sectors?
   - "yes": directly matches primary sectors (AI, fintech, gamedev, devtools, infra, automation)
   - "partial": matches adjacent sectors (SaaS, B2B, analytics, cybersecurity, etc.)
   - "no": does not match any thesis sectors

4. **product_type** — What type of product is this?
   - "software": SaaS, app, platform, API, cloud service, AI model
   - "hardware": physical devices, robots, chips, sensors
   - "biotech": pharma, medical devices, genetic engineering
   - "service": consulting, marketplace connecting people, manual services
   - "other": none of the above

5. **b2b_b2c** — Who is the customer?
   - "b2b": sells to businesses
   - "b2c": sells to consumers
   - "both": serves both
   - "unknown": cannot determine from description

Respond with a JSON object containing exactly these keys:
{"is_tech": true, "sector": "AI/ML", "sector_match": "yes", "product_type": "software", "b2b_b2c": "b2b"}

Be decisive. When in doubt about sector_match, prefer "partial" over "no" — the scoring formula handles precision.
```

Rewrite pipeline/prefilter.py with three stages:

Imports: asyncio, os, pathlib.Path, shutil, yaml, frontmatter, re, from lib.llm import call_llm, load_prompt, from lib.utils import load_idea, save_idea

Constants:
- IDEAS_DIR = Path("1_ideas")
- ARCHIVE_DIR = Path("_archive")
- FILTERS_PATH = Path("config/filters.yaml")

Function `def load_filters() -> dict`:
- yaml.safe_load from FILTERS_PATH

Function `def hard_reject(post: frontmatter.Post, filters: dict) -> str | None`:
- Check description length (same word-boundary regex for exclude_niches as before)
- Check exclude_niches keyword match (keep existing regex logic)
- Check round_usd >= max_round_usd
- Return rejection reason string or None if passed

Function `async def classify_one(post: frontmatter.Post, prompt_template: str) -> dict | None`:
- Build prompt using .replace() for {name}, {url}, {round_raw}, {description}
- Call LLM with json_mode=True, model=OPENROUTER_MODEL_LIGHT
- Validate required keys: is_tech, sector, sector_match, product_type, b2b_b2c
- Return parsed dict or None on failure

Function `def compute_eligibility(post: frontmatter.Post, filters: dict) -> tuple[bool, bool]`:
- invest_eligible = (post["is_tech"] == True) AND (post["sector_match"] in ("yes", "partial")) AND (filters["invest_round_min"] <= (post.get("round_usd") or 0) <= filters["invest_round_max"])
- build_eligible = (post["is_tech"] == True) AND (post["sector_match"] in ("yes", "partial")) AND (post["product_type"] in ("software", "service"))
- Return (invest_eligible, build_eligible)

Function `async def run_prefilter() -> dict`:
- Load filters, load classify prompt
- Stage A: iterate all 1_ideas/*.md, skip already-processed (have "invest_eligible" key), apply hard_reject. Archive rejects. Collect survivors.
- Stage B: run classify_one on all survivors via asyncio.gather (with return_exceptions=True). Write classification fields to frontmatter (is_tech, sector, sector_match, product_type, b2b_b2c).
- Stage C: compute eligibility for each classified idea. Write invest_eligible and build_eligible to frontmatter. Also write filtered="passed" for backward compat. Archive those with both False.
- Print summary: "Pre-filter: {hard_rejected} hard rejected, {classified} classified, {invest_count} invest-eligible, {build_count} build-eligible, {archived} archived"
- Return stats dict

Keep idempotency: skip ideas that already have invest_eligible in frontmatter.
Keep backward compatibility: still write `filtered: "passed"` for ideas that pass, so downstream modules work without changes during transition.

Rewrite pipeline/quick_score.py with formula-based scoring:

Imports: asyncio, os, pathlib.Path, yaml, frontmatter, from lib.llm import call_llm, load_prompt, from lib.utils import load_idea, save_idea

Constants:
- IDEAS_DIR = Path("1_ideas")
- FORMULA_PATH = Path("config/scoring_formula.yaml")

Function `def load_formula() -> dict`:
- yaml.safe_load from FORMULA_PATH

Function `def compute_round_fit(round_usd: int | None) -> str`:
- If round_usd is None: return "far"
- If 30_000 <= round_usd <= 300_000: return "in_range"
- If 300_000 < round_usd <= 2_000_000: return "close"
- Else: return "far"

Function `def compute_score(answers: dict, formula: dict) -> int`:
- total = 0
- For each factor_name, value_map in formula.items():
    answer_value = answers.get(factor_name, "unknown")
    if isinstance(answer_value, str): answer_value = answer_value.lower()
    points = value_map.get(answer_value, 0)
    total += points
- Return max(0, min(10, total))

Function `async def score_one_idea(post: frontmatter.Post, prompt_template: str) -> dict | None`:
- Build prompt using .replace() for {name}, {url}, {round_raw}, {description}, {sector} (from prefilter), {product_type} (from prefilter)
- Call LLM with json_mode=True, model=OPENROUTER_MODEL_LIGHT
- Validate required keys: has_product_signal, founder_signal, cis_transferable, uniqueness, market_potential, one_liner, category, invest_rationale, build_rationale
- Return parsed dict or None on failure

Function `async def run_quick_score() -> dict`:
- Load formula and prompt
- Scan IDEAS_DIR for ideas with filtered=="passed" and no invest_score yet
- Score each via asyncio.gather
- For each successful result:
    - Merge prefilter fields into scoring answers: sector_match, product_type, b2b_b2c (read from post frontmatter)
    - Add round_fit = compute_round_fit(post.get("round_usd"))
    - Rename: has_product_signal → has_product (to match formula key)
    - Compute invest_score = compute_score(answers, formula["invest_formula"])
    - Compute build_score = compute_score(answers, formula["build_formula"])
    - Write ALL fields to frontmatter: has_product_signal, founder_signal, cis_transferable, uniqueness, market_potential, invest_score, build_score, one_liner, category, invest_rationale, build_rationale
    - save_idea
- Build shortlist: invest_score >= formula["shortlist"]["invest_threshold"] OR build_score >= formula["shortlist"]["build_threshold"]
- Print summary
- Return stats dict

Key difference from before: invest_score and build_score are COMPUTED from formula, not LLM-returned numbers.
