Problems solved:
1. Build score inflated (63% pass threshold) because formula gives 8-9 to any B2B software

3. No gate between research and analysis — all 190 researched go to expensive heavy model
4. invest_score/build_score at triage misleading — implies final judgment from 1-sentence data
5. Unknown founder penalized as bad founder — data absence ≠ negative evidence

Architecture: hard filter → classify → triage → research → research_gate → heavy analysis → digest
Target funnel: 424 → ~300 → 30-60 → 10-20 analyzed
</objective>

```
You are screening startup funding announcements for iFree, a tech company that invests in seed-stage startups ($30K-$300K) and builds own products in AI, fintech, gamedev, devtools, infrastructure, and automation.

You will see a BRIEF funding announcement — typically just a company name, URL, round amount, and 1-2 sentence description. This is minimal data.

## Important calibration

Most startups (60-70%) in a typical deal flow batch will have:
- NO evidence of a working product in their brief description
- NO founder information visible
- A generic description that could apply to many companies

This is NORMAL — it means the data source is thin, NOT that the startup is bad. Answer based on what IS present, not what is missing.

## Startup Data

**Name:** {name}
**URL:** {url}
**Round:** {round_raw}
**Sector:** {sector}
**Product type:** {product_type}
**Description:** {description}

## Answer these questions:

1. **has_product_evidence** — Does the description explicitly mention any of: actual users, paying customers, revenue numbers, specific integrations, metrics, or a live product with described features?
   - Answer "no" FIRST if none of these are explicitly stated. A marketing tagline ("AI-powered platform for X") is NOT product evidence.
   - Answer "yes" ONLY if the description contains concrete evidence: user counts, revenue, customer names, integration details, or specific feature descriptions that go beyond a tagline.

2. **has_founder_signal** — Does the description mention founder names, prior company experience, exits, technical credentials, or notable affiliations?
   - Answer "no" FIRST — most funding announcements do not include founder details.
   - Answer "yes" ONLY if specific founder credentials are mentioned.

3. **barriers** — List 2-3 specific barriers or risks for this startup. Be concrete (e.g., "crowded market with Stripe, Square, Adyen as incumbents", "requires regulatory approval in each market").

4. **one_liner** — One sentence summary in Russian for the team digest.

5. **category** — Specific niche string (e.g., "AI code review", "B2B payments infrastructure", "edge ML for IoT").

## Examples

Example 1 (both NO):
Input: "Acme Corp — $500K — AI-powered platform for business automation"
Output: {"has_product_evidence": false, "has_founder_signal": false, "barriers": ["generic description — unclear what specific problem is solved", "extremely crowded AI automation space"], "one_liner": "AI-платформа для автоматизации бизнес-процессов, без деталей о продукте", "category": "AI business automation"}

Example 2 (both NO):
Input: "DataSync — $1.2M — Real-time data synchronization across cloud providers"
Output: {"has_product_evidence": false, "has_founder_signal": false, "barriers": ["competing with established ETL tools (Fivetran, Airbyte)", "requires deep integration with each cloud provider"], "one_liner": "Синхронизация данных между облачными провайдерами в реальном времени", "category": "data infrastructure"}

Example 3 (product YES):
Input: "CodeLens — $200K — AI code review used by 340 teams including Shopify and Stripe. Catches 40% more bugs than existing linters."
Output: {"has_product_evidence": true, "has_founder_signal": false, "barriers": ["GitHub Copilot and similar tools expanding into code review", "enterprise sales cycle for security-sensitive tooling"], "one_liner": "AI код-ревью, используется 340 командами включая Shopify и Stripe — ловит на 40% больше багов", "category": "AI code review"}

Respond with JSON containing exactly these 5 keys. Remember: "no" is the expected default for questions 1 and 2 given the data source.
```

```
   - "yes": concrete numbers or named customers found
   - "no": no quantitative traction data

3. **has_competitive_context** — Did the research identify the competitive landscape? Named competitors, market positioning, differentiation?

   - "no": generic or no competitive data

### Track B: Build Opportunity Signals

iFree context: tech company focused on AI, fintech, gamedev, devtools. Has B2B clients. Based in Russia, interested in CIS market opportunities.

4. **underserved_niche** — Based on competitive data, are there multiple small players but no dominant market leader?
   - "yes": research found fragmented market with no clear winner
   - "no": dominant player exists, OR market is too early/unclear

5. **clear_localization_path** — Could this product be adapted for CIS market in under 3 months?
   - "yes": software-only, no regulatory barriers, language is the main adaptation needed
   - "no": requires regulatory compliance, local partnerships, significant re-engineering
   DEFAULT: "no" — only "yes" if the path is genuinely simple

Respond with JSON containing exactly 8 keys (3 invest + 5 build). Default to "no" unless evidence supports "yes".
```

Create pipeline/triage.py (NEW file, does NOT modify quick_score.py — that gets deleted in Task 4):

Imports: asyncio, os, pathlib.Path, yaml, frontmatter, from lib.llm import call_llm, load_prompt, from lib.utils import load_idea, save_idea

Constants:
- IDEAS_DIR = Path("1_ideas")
- CONFIG_PATH = Path("config/triage.yaml")

Function `def load_triage_config() -> dict`:
- yaml.safe_load from CONFIG_PATH

Function `def is_round_in_range(round_usd: int | None) -> bool`:
- Return True if round_usd is not None and 30_000 <= round_usd <= 2_000_000
- None → False (not enough data, but NOT negative evidence)

Function `async def triage_one(post: frontmatter.Post, prompt_template: str) -> dict | None`:
- Build prompt using .replace() for {name}, {url}, {round_raw}, {description}, {sector}, {product_type}
- Call LLM with json_mode=True, model=OPENROUTER_MODEL_LIGHT
- REQUIRED_KEYS = {"has_product_evidence", "has_founder_signal", "barriers", "one_liner", "category"}
- Coerce has_product_evidence and has_founder_signal to bool (handle "yes"/"no"/true/false/True/False)
- Return parsed dict or None on failure

Function `def compute_invest_priority(post: frontmatter.Post, triage_result: dict, config: dict) -> str`:
- Count yes signals:
    sector_fit = post.get("sector_match") in ("yes", "partial")
    round_in_range = is_round_in_range(post.get("round_usd"))
    has_product = triage_result.get("has_product_evidence", False)
    has_founder = triage_result.get("has_founder_signal", False)
    signal_count = sum([sector_fit, round_in_range, has_product, has_founder])
- thresholds = config["invest_priority_thresholds"]
- if signal_count >= thresholds["high"]: return "high"
- if signal_count >= thresholds["medium"]: return "medium"
- return "low"

Function `def compute_build_candidate(post: frontmatter.Post, config: dict) -> bool`:
- req = config["build_candidate_requires"]
- Return (post.get("is_tech") == True
          AND post.get("product_type") in req["product_type"]
          AND post.get("sector_match") in req["sector_match"])

Function `async def run_triage() -> dict`:
- Load config and prompt
- Scan IDEAS_DIR for ideas with filtered=="passed" and no invest_priority yet
- Call triage_one for each via asyncio.gather(return_exceptions=True)
- For each result:
    invest_priority = compute_invest_priority(post, result, config)
    build_candidate = compute_build_candidate(post, config)
    Write to frontmatter: invest_priority, build_candidate, has_product_evidence,
      has_founder_signal, barriers, one_liner, category
    save_idea
- Build research list: ideas where invest_priority != "low" OR build_candidate == true
- Print summary with priority distribution
- Return stats dict with research_list

if __name__ == "__main__": asyncio.run(run_triage())

Imports: asyncio, os, pathlib.Path, yaml, frontmatter, from lib.llm import call_llm, load_prompt, from lib.utils import load_idea, save_idea, make_slug

Function `async def evaluate_one(slug: str, research_dir: Path, idea_post: frontmatter.Post, prompt_template: str) -> dict | None`:
- Load website.md and web_research.md from research_dir
- Build prompt using .replace() for {name}, {url}, {round_raw}, {description}, {sector}, {website_content} (first 3000 chars), {research_notes} (first 3000 chars)
- Call LLM with json_mode=True, model=OPENROUTER_MODEL_LIGHT
- REQUIRED_KEYS = {"has_team_data", "has_traction_data", "has_competitive_context", "ru_gap_detected", "oss_commercializable", "cross_sell_fit", "underserved_niche", "clear_localization_path"}
- Coerce all values to bool (handle "yes"/"no"/true/false)
- Return parsed dict or None on failure (with fallback: all False)

Function `def compute_analysis_ready(gate_result: dict, config: dict) -> bool`:
- invest_evidence = sum([gate_result.get("has_team_data", False), gate_result.get("has_traction_data", False), gate_result.get("has_competitive_context", False)])
- invest_ready = invest_evidence >= config["research_gate"]["invest_evidence_threshold"]
- rare_signals = config["research_gate"]["build_rare_signals"]
- build_ready = any(gate_result.get(sig, False) for sig in rare_signals)
- Return invest_ready OR build_ready

Function `def compute_build_priority(gate_result: dict, config: dict) -> str`:
- rare_signals = config["research_gate"]["build_rare_signals"]
- has_rare = any(gate_result.get(sig, False) for sig in rare_signals)
- If has_rare: return "high"
- Return "medium" (build_candidate was already true to reach this stage)

Function `async def run_research_gate() -> dict`:
- Load config and prompt
- Scan RESEARCH_DIR for all slugs with web_research.md
- For each: find matching idea in IDEAS_DIR, call evaluate_one
- Compute analysis_ready and build_priority
- Write gate.md to 2_research/{slug}/ with structured results
- Update idea frontmatter: analysis_ready, build_priority, and all 8 signal fields
- Print summary: "{ready} analysis-ready, {not_ready} filtered out, {rare_count} with rare build signals"
- Return stats dict with analysis_ready_slugs list

if __name__ == "__main__": asyncio.run(run_research_gate())
