<objective>
Enrich the context passed to both Parallel AI (Stage 7.5) and deep_analysis LLM (Stage 8) so that scoring and executive summaries are built on the strongest possible foundation — RAW Stage 5 bucketed search results (independent evidence) plus the Stage 7 gate interpretation that already exist on disk.

Purpose: Currently Parallel AI only receives triage-level data (name, description, build_thesis) — ignoring both (a) the ~70KB of bucketed search results in `2_research/{slug}/build_research_raw.json` (titles, URLs, snippets across CIS_PLAYERS / DEMAND_SIGNAL / GLOBAL_ALT / OSS_BASE / COMMUNITY) and (b) the ~3KB Stage 5 LLM synthesis in `build_research.md`. Similarly, Stage 8 reads `deep_research.md` but NOT `gate_build.md`, missing the gate's structured interpretation (5 boolean signals + decision).

Anti-anchoring design (the critical bit): we send the **raw evidence as PRIMARY** input (it is independent fact, just URLs+snippets) and the **LLM-synthesized summary as SECONDARY** hint. This is the opposite of the naive "feed the digest" approach — that would re-anchor Parallel AI on the cheap DDG+LLM layer's mistakes. Both the prompt framing and the section ordering enforce this: raw evidence is shown first under "validate or refute", summary appears below it as "cheap-LLM interpretation, may be wrong".

This plan closes both gaps by:
1. Threading raw bucket evidence (titles+URLs+short snippets) into Parallel AI as primary independent data.
2. Keeping the LLM-synthesized summary as a secondary hint, explicitly framed.
3. Threading gate signals into both Stage 7.5 (validate-or-refute) and Stage 8 (interpretation hint, deep_research.md remains source of truth).
4. Extracting the shared gate parser + raw evidence formatter into `lib/research_utils.py` so both pipeline modules import from `lib/`, never from each other.

### ADR — why this plan matters for Phase 2 strategy

Phase 2 (per ROADMAP.md line 23-37) shipped two strategic decisions that 02-04 is **directly load-bearing** for:

1. **Deterministic-first digest (02-03):** `pipeline/digest_generator.py` now copies `executive_summary` byte-for-byte from `3_analysis/{slug}.md` into the daily digest. The LLM only synthesizes a narrow `key_findings + trends` JSON. **Implication:** the executive_summary is now the *single quality lever* for the digest. It is produced by Stage 8 (`pipeline/deep_analysis.py`). 02-04 enriches Stage 8's input (gate_signals) AND Stage 7.5's input (raw evidence + summary + gate) — Stage 7.5 produces `deep_research.md`, which is Stage 8's primary input. Better Stage 7.5 context → better deep_research.md → better executive_summary → better digest. Without 02-04, the deterministic digest is locked to whatever quality the un-enriched Stage 7.5 + Stage 8 currently produce.

2. **Canonical verdict taxonomy + killed routing (ROADMAP line 28):** `build_verdict ∈ {BUILD, PARTNER, MONITOR, SKIP}` with a separate `killed: bool` + `kill_reason: str`. Kill signals (рынок занят, высокий капитал, далеко от компетенций, >6мес до выручки) are computed by Stage 8. Threading `gate_signals` into Stage 8 directly informs the "рынок занят" kill detection: when Stage 7's gate already saw `cis_gap_confirmed=False` AND `market_demand_signals=True`, Stage 8 should much more reliably trigger killed=True with kill_reason="рынок занят". Without gate_signals at Stage 8, kill signals depend solely on the deep_research.md narrative — fragile.

This ADR-style note documents *why* 02-04 is not just polish on prompts — it is the quality bridge between 02-02 (analysis architecture) and 02-03 (deterministic digest output) that turns the strategic Phase 2 plumbing into management-ready output Дина actually wants.

### Part A — create lib/research_utils.py (NEW file)

Create `lib/research_utils.py` as the single source of truth for parsing two files that both `pipeline/deep_research_v2.py` and `pipeline/deep_analysis.py` need to read. **This module lives in `lib/`, not `pipeline/`, because both pipeline stages depend on it — Task 2 will import the gate helper from here, NOT from `deep_research_v2.py`.**

Two helpers, both pure-functional, both graceful, both string-returning:

```python
"""Shared helpers for reading Stage 5/7 research artifacts as prompt context.

Both helpers are GRACEFUL: missing/malformed file → explicit placeholder
string, never raises. The pipeline must not block on one bad startup.

Module placement rationale: these helpers are consumed by both
pipeline/deep_research_v2.py (Stage 7.5) and pipeline/deep_analysis.py
(Stage 8). Keeping them in lib/ avoids cross-stage coupling between
two pipeline modules.
"""
from __future__ import annotations

import json
from pathlib import Path


def _format_gate_signals(gate_path: Path) -> str:
    """Parse 2_research/{slug}/gate_build.md into a human-readable signal block.

    Output format (consumed verbatim by prompts):
        - cis_gap_confirmed: False
        - replicable_confirmed: False
        - oss_base_available: False
        - market_demand_signals: True
        - clear_localization_path: False
        Decision: build_analysis_ready=False, build_priority=medium
    """
    if not gate_path.exists():
        return "(Stage 7 gate signals not available)"
    try:
        text = gate_path.read_text(encoding="utf-8")
    except Exception:
        return "(Stage 7 gate signals not available — read error)"
    # Line-by-line scan beats regex here: the file is small and deterministic
    # (generated by pipeline/build_gate.py), and a scan is easier to debug.
    signals: list[str] = []
    decision: list[str] = []
    section: str | None = None
    for line in text.splitlines():
        s = line.strip()
        if s.startswith("## Build Signals"):
            section = "signals"
            continue
        if s.startswith("## Decision"):
            section = "decision"
            continue
        if s.startswith("## "):
            section = None
            continue
        if section == "signals" and s.startswith("- "):
            signals.append(s)
        elif section == "decision" and s.startswith("- "):
            decision.append(s.lstrip("- "))
    if not signals and not decision:
        return "(Stage 7 gate signals not available — no parseable content)"
    parts: list[str] = list(signals)
    if decision:
        parts.append("Decision: " + ", ".join(decision))
    return "\n".join(parts)


def _format_raw_evidence(raw_path: Path, max_chars: int = 6000) -> str:
    """Compact `build_research_raw.json` into a prompt-friendly evidence block.

    Why this exists: `build_research.md` is a heavily-compressed LLM synthesis
    of the raw search results. Feeding ONLY the markdown re-anchors Parallel
    AI on the cheap DDG+LLM layer's interpretation. Feeding the raw JSON's
    independent evidence (titles + URLs + short snippets across all buckets)
    lets Parallel AI form its own opinion before it sees our synthesis.

    Per-result format (compact — title and URL are the high-signal bits;
    a short snippet preserves enough context for Parallel AI to know whether
    to follow the URL):
        - <url>
          <title>
          <snippet[:200]>

    Buckets are emitted in fixed order with their query so Parallel AI can
    judge whether the query was reasonable. `max_chars` is a hard cap;
    excess buckets are truncated with an explicit note.

    Returns "(Stage 5 raw evidence not available)" / "(... — read error)" /
    "(... — malformed JSON)" placeholder strings when the file is missing
    or unparseable. Never raises.
    """
    if not raw_path.exists():
        return "(Stage 5 raw evidence not available)"
    try:
        payload = json.loads(raw_path.read_text(encoding="utf-8"))
    except OSError:
        return "(Stage 5 raw evidence not available — read error)"
    except json.JSONDecodeError:
        return "(Stage 5 raw evidence not available — malformed JSON)"
    buckets = payload.get("buckets") or {}
    if not isinstance(buckets, dict) or not buckets:
        return "(Stage 5 raw evidence not available — no buckets)"

    bucket_order = ["CIS_PLAYERS", "DEMAND_SIGNAL", "GLOBAL_ALT", "OSS_BASE", "COMMUNITY"]
    seen = set(bucket_order)
    ordered = [b for b in bucket_order if b in buckets] + [
        b for b in buckets.keys() if b not in seen
    ]

    out: list[str] = []
    for bucket_name in ordered:
        bucket = buckets.get(bucket_name) or {}
        results = bucket.get("results") or []
        query = bucket.get("query", "")
        out.append(f"=== {bucket_name} (query: {query!r}, n={len(results)}) ===")
        for r in results:
            url = (r.get("url") or "").strip()
            title = (r.get("title") or "").strip().replace("\n", " ")
            snippet = (r.get("text") or "").strip().replace("\n", " ")
            out.append(f"- {url}")
            if title:
                out.append(f"  {title[:200]}")
            if snippet:
                out.append(f"  {snippet[:200]}")

    text = "\n".join(out)
    if len(text) > max_chars:
        text = text[:max_chars] + f"\n[... truncated to {max_chars} chars ...]"
    return text
```
