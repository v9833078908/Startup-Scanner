**Дата:** 2026-04-13
**Автор:** Илья Ефимов
**Контекст:** Результат интервью + анализ текущего пайплайна + фидбек от Дины (встреча 13.04.26)

## Проблема

Текущий пайплайн выдаёт "пустые звуки" — описания вроде "Deeptrace: автоматизация дебаггинга с ИИ" или "Lucky: предоставление бесплатных денег при покупках". Этого катастрофически мало для принятия управленческих решений.

**Корневая причина:** Deep analysis (Stage 8) работает на скудных данных — Stage 5 (Build Research) делает всего 3 поиска через DuckDuckGo, и Gemini 2.5 Pro вынужден скорить и описывать стартапы на основе минимальной фактуры.

**Аудитория отчёта:** Василий + Дина + акционеры — стратегические решения о запуске новых продуктов. Документ должен быть самодостаточным.

---

## Известные слабые места пайплайна

### 1. Triage (Stage 3) принимает решения "из головы LLM"

**`has_founder_signal`** — промпт говорит: "Answer 'no' FIRST — most funding announcements do not include founder details." В 90% случаев ответ `false`. LLM не гуглит фаундеров — просто проверяет, упоминается ли что-то в описании DealPad. Почти никогда нет. Это проверка наличия текста, а не оценка качества фаундера.

**`cis_gap_likelihood`** — LLM отвечает на вопрос "Is this product US/EU-focused with no obvious equivalent in Russia/CIS?" из общих знаний. Для Stripe-подобного продукта Gemini Flash знает, что в России есть ЮKassa/Тинькофф — ответит `false`. Но для нишевого стартапа — гадает.

Ошибки на этом этапе:
- **False negative** (пропустил хороший стартап) — плохо, но triage настроен мягко
- **False positive** (пропустил плохой) — не страшно, build gate потом отфильтрует

**Вывод:** Triage работает как грубый фильтр, и это ок на данном этапе. Но нужно осознавать, что решения на Stage 3 — это "лучшее предположение LLM", а не факты. Настоящая валидация происходит только на deep research.

### 2. Build Research (Stage 5) — слишком мало данных

3 поиска через DuckDuckGo (бесплатный, точность ~3/10):
- `{category} Россия`
- `{category} аналог CIS`
- `{name} open source alternative github`

Этого недостаточно для формирования качественной фактуры. Результат — build gate и deep analysis работают на "пустоте".

### 3. Deep Analysis (Stage 8) — скорит без контекста

Gemini 2.5 Pro получает ~3000 символов research notes и должен оценить 8 критериев. Без данных о TAM, конкурентах, бизнес-модели — оценки поверхностные, описания generic.

### 4. Digest (Stage 9) — "пустые звуки" в выдаче

One-liners типа "AI для контроля в реальном времени" ничего не говорят. CIS-адаптация шаблонная ("русский UI, Яндекс.Облако, ФЗ-152"). Нет сути бизнеса, нет TAM, нет понимания кто клиент.

---

## Решение: новая стадия Deep Research + обновление Stage 8 и 9

### Архитектура (до и после)

**Сейчас:**
```
Stage 7 (Build Gate) → 11-20 стартапов
    ↓
Stage 8 (Deep Analysis) → скоринг на СКУДНЫХ данных
    ↓
Stage 9 (Digest) → "пустые звуки"
```

**После:**
```
Stage 7 (Build Gate) → 11-20 стартапов
    ↓
Stage 7.5 [NEW] Deep Research → автономное исследование через API
    ↓
Stage 8 (Deep Analysis) → kill-сигналы + скоринг на БОГАТОЙ фактуре + executive summary
    ↓
Stage 9 (Digest) → информативный отчёт для руководства
```

**Что НЕ трогаем:** Stage 1-4, 6-7 (parse, prefilter, triage, invest research, gates) — воронка работает нормально.

## Stage 7.5 [NEW]: Deep Research

### Суть

Для каждого стартапа, прошедшего build gate (~11-20 шт.), запускается автономное deep research исследование через платный API. API самостоятельно ищет в интернете, читает источники, синтезирует отчёт.

### Выбор API

| Сервис | Автономное исследование | Стоимость/запрос | Качество |
|--------|------------------------|-----------------|----------|
| **OpenAI o3-deep-research** | Да | $0.50-5.00 | Максимальное |
| **Perplexity Sonar Deep Research** | Да | $0.05-0.50 | Высокое |
| **You.com Research API** | Да, 5 уровней глубины | $0.007+ | Высокое (лучшие бенчмарки) |
| **Exa Deep** | Да (агентный поиск) | $0.012 | Среднее |
| **Google Gemini Deep Research** | Да | $2-5 за задачу | Высокое, preview |

При 20 стартапах и бюджете ~$50/неделя:
- Perplexity: $1-10 за прогон
- You.com: гибкие тиры
- OpenAI o3: $10-100 за прогон

**Решение:** TBD — протестировать 2-3 API на одном стартапе и сравнить качество.

### Research Brief (промпт для deep research API)

```markdown
## Задача

Проведи глубокое исследование стартапа {name} ({url}).

Контекст: мы — стартап-студия, оцениваем возможность создать 
аналогичный продукт. Нам нужна фактура для принятия решения: 
строить или нет.

Известно на входе:
- Описание: {description}
- Раунд: {round_raw}
- Категория: {category}

## Что исследовать

### 1. Суть бизнеса
- Что конкретно делает продукт (не buzzwords, а механика)
- Какую проблему решает и насколько она острая
- Кто платит (ICP — ideal customer profile)
- Бизнес-модель и ценообразование

### 2. Размер рынка (TAM)
- Bottom-up оценка: количество потенциальных клиентов × средний чек
- Динамика рынка: растёт, стагнирует, сжимается
- Ключевые драйверы роста или торможения

### 3. Конкурентная среда
- Глобальные конкуренты (прямые и косвенные)
- Конкуренты на потенциальных целевых рынках (Россия, СНГ, MENA, 
  SEA, LATAM — определи где есть gap)
- Кто доминирует и почему, есть ли пустое место

### 4. Валидация и traction оригинала
- Выручка, пользователи, рост (если данные публичны)
- Отзывы пользователей (G2, Capterra, Product Hunt, Reddit)
- Инвесторы и их репутация

### 5. Оценка возможности build
- Техническая сложность: что под капотом, какой стек нужен
- Время до MVP: сколько месяцев, какая команда
- Время до первой выручки: реалистичная оценка
- Регуляторные барьеры на целевом рынке
- Ключевые риски при создании аналога

### 6. Рекомендация по географии
- На каком рынке имеет смысл строить аналог и почему
- Основывайся на данных: где спрос, где пусто, где проще зайти

## Формат ответа

По каждому разделу: факты и цифры со ссылками на источники.
Если данных нет — явно пиши "данные не найдены", не додумывай.
Объём: 800-1500 слов.
Язык: русский, технические термины на английском.
```

### Выходной файл

`2_research/{slug}/deep_research.md` — полный отчёт исследования со ссылками на источники.

## Stage 8: Deep Analysis (обновление)

### Что меняется

- Получает на вход `deep_research.md` вместо скудных research notes
- Добавляются **kill-сигналы** как жёсткий фильтр до скоринга
- Формирует **executive summary** для руководства
- Скоринг остаётся (бэкенд), числа не выводятся в HTML-отчёт

### Kill-сигналы (авто-PASS)

Проверяются до скоринга. Если хотя бы один = true → вердикт PASS:

1. **Рынок занят** — на целевом рынке сильный локальный игрок с >30% доли или сильным брендом
2. **Высокий капитал на вход** — значительные инвестиции на старте (инфраструктура, лицензии, hardware)
3. **Далеко от компетенций i-Free** — требует экспертизы, которой нет (biotech, hardware, deep domain)
4. **>6 месяцев до первой выручки** — от старта разработки до первых платящих клиентов

### Критерии скоринга (build mode)

| Критерий | Вес | На что смотреть |
|----------|-----|-----------------|
| market_opportunity | 30% | TAM, рост рынка, наличие gap |
| ifree_fit | 25% | Совпадение с компетенциями, размер команды |
| technical_feasibility | 15% | Сложность, доступность стека |
| speed_to_market | 10% | Месяцы до MVP, до первой выручки |
| revenue_potential | 10% | Бизнес-модель, unit-экономика, чек |
| defensibility | 5% | Что мешает скопировать наш аналог |
| trend_alignment | 3% | Совпадение с трендами рынка |
| gut_feeling | 2% | Общее ощущение от возможности |

### Executive Summary (формат по каждому стартапу)

```markdown
### {name} — {verdict}

**Суть:** [2-3 предложения — что делает, какую проблему решает, для кого]

**Рынок:** [TAM, рост, ключевые игроки — 2-3 предложения]

**Что строить:** [MVP scope, первые клиенты, канал продаж — самая суть]

**Целевой рынок:** [география и почему именно она — 1-2 предложения]

**Time to market:** [до MVP / до первой выручки]

**Ключевые риски:** [2-3 главных риска]
```

### Промпт `deep_analysis.md`

```markdown
## Роль

Ты — аналитик стартап-студии i-Free. Твоя задача — оценить стартап 
и дать рекомендацию: строить аналог или нет.

Аудитория твоего анализа — руководство и акционеры, принимающие 
стратегические решения о запуске новых продуктов.

## Контекст i-Free

- Стартап-студия, 20+ лет, фокус: AI, Fintech, NFC
- Портфель: Just AI (разговорный AI), CoinKeeper (PFM), NaLunch (фудтех)
- Компетенции: backend, AI/ML, мобильная разработка, платёжные системы
- Ресурс: небольшие команды (3-5 разработчиков)

## Входные данные

- Стартап: {name} ({url})
- Раунд: {round_raw}
- Категория: {category}
- Результат deep research: {deep_research_content}

## Шаг 1: Kill-сигналы (жёсткий фильтр)

Проверь каждый. Если хотя бы один = true → вердикт PASS, 
дальнейший анализ не нужен. Объясни почему.

1. **Рынок занят** — на целевом рынке уже есть сильный локальный 
   игрок с >30% доли или сильным брендом, которого нереалистично 
   потеснить
2. **Высокий капитал на вход** — для запуска MVP нужны значительные 
   инвестиции (инфраструктура, лицензии, hardware, контент)
3. **Далеко от компетенций i-Free** — требует экспертизы, которой 
   нет (biotech, hardware, deep domain knowledge в регулируемых 
   отраслях)
4. **>6 месяцев до первой выручки** — от старта разработки до 
   первых платящих клиентов больше 6 месяцев

## Шаг 2: Скоринг (build mode)

Оцени по критериям (1-10, с обоснованием):

| Критерий | Вес | На что смотреть |
|----------|-----|-----------------|
| market_opportunity | 30% | TAM, рост рынка, наличие gap |
| ifree_fit | 25% | Совпадение с компетенциями, размер команды |
| technical_feasibility | 15% | Сложность, доступность стека |
| speed_to_market | 10% | Месяцы до MVP, до первой выручки |
| revenue_potential | 10% | Бизнес-модель, unit-экономика, чек |
| defensibility | 5% | Что мешает скопировать наш аналог |
| trend_alignment | 3% | Совпадение с трендами рынка |
| gut_feeling | 2% | Общее ощущение от возможности |

## Шаг 3: Executive Summary

Сформируй краткое резюме для руководства:

### {name} — {verdict}

**Суть:** [2-3 предложения — что делает, какую проблему решает, 
для кого]

**Рынок:** [TAM, рост, ключевые игроки — 2-3 предложения]

**Что строить:** [MVP scope, первые клиенты, канал продаж — 
самая суть]

**Целевой рынок:** [география и почему именно она — 1-2 предложения]

**Time to market:** [до MVP / до первой выручки]

**Ключевые риски:** [2-3 главных риска]

**Вердикт:** BUILD / PARTNER / MONITOR / SKIP + одно предложение 
почему

## Формат ответа

JSON:
- kill_signals: {signal_name: {triggered: bool, reason: string}}
- killed: bool
- build_scoring: {criterion: {score: int, rationale: string}}
- build_total: float
- build_verdict: string (BUILD / PARTNER / MONITOR / SKIP)
- executive_summary: string (markdown, структура из Шага 3)
- red_flags: [string]
- green_flags: [string]
- recommended_market: string
- time_to_mvp: string
- time_to_revenue: string
```

## Stage 9: Digest (обновление)

### Что меняется

- Executive summary из Stage 8 попадает прямо в дайджест (не пересочиняется)
- WATCH/MONITOR — не one-liner, а 2-3 информативных предложения
- PASS — показываем с причиной (какой kill-сигнал сработал)
- Числовой скоринг не выводится
- Тренды недели остаются

### Промпт `digest.md`

```markdown
## Роль

Ты составляешь еженедельный дайджест стартап-скаутинга для 
руководства стартап-студии i-Free (Василий, Дина, акционеры).

Цель дайджеста — дать достаточно информации для принятия решения: 
какие идеи стоит рассмотреть для создания аналога.

## Входные данные

{analysis_data}

## Структура дайджеста

### 1. Pipeline Summary

Воронка отбора — сколько на входе, сколько на каждом этапе, 
сколько дошло до финала. Кратко, в цифрах.

### 2. Ключевые находки недели

2-3 предложения: что интересного, какие тренды, есть ли 
что-то необычное.

### 3. BUILD рекомендации

Для каждого стартапа с вердиктом BUILD или PARTNER — 
executive summary из deep analysis:

**{name} — {verdict}**

**Суть:** [что делает, какую проблему решает, для кого]

**Рынок:** [TAM, рост, конкурентная среда]

**Что строить:** [MVP, первые клиенты, канал продаж — самая суть]

**Целевой рынок:** [география и почему]

**Time to market:** [до MVP / до первой выручки]

**Ключевые риски:** [2-3 риска]

Сортировка: от наиболее перспективных к менее.

### 4. WATCH / MONITOR

Таблица стартапов, которые не прошли в BUILD, но заслуживают 
внимания. Формат: название, категория, раунд, суть в 2-3 
информативных предложения (не one-liner, а понятное описание 
бизнеса и почему он в WATCH).

### 5. PASS с kill-сигналами

Краткая таблица: название, какой kill-сигнал сработал, одно 
предложение почему. Для прозрачности — руководство видит что 
отсеяно и почему.

### 6. Тренды недели

- Топ-3 категории по количеству стартапов
- Паттерны: куда идут инвестиции, что набирает обороты
- Сигналы из нескольких источников

## Правила

- Язык: русский, технические термины на английском
- Не выводить числовой скоринг — только вердикты
- Каждое описание самодостаточно — читатель не должен гуглить
- Если данных мало — писать "недостаточно данных", не додумывать
- Термины и аббревиатуры расшифровывать при первом упоминании
- Не писать очевидное ("поддержка русского языка", "рублёвые цены")
```

## Требования к результату

**Для руководства (дайджест):**
- Каждый стартап — executive summary, достаточный для go/no-go
- Суть бизнеса понятна без гугления
- Kill-сигналы прозрачны — видно что и почему отсеяно
- Без числового скоринга в интерфейсе
- Рекомендованная география определяется данными, не предустановкой "СНГ"

**Для пайплайна:**
- Deep research только для финалистов (~11-20 из ~400) — экономия бюджета
- Скоринг сохраняется в бэкенде (md-файлы)
- Idempotent — безопасно перезапускать
- Stage 1-7 без изменений
